# Token/community receipt hygiene

Status: seeded

## Trigger

Use when publishing token/community instrumentation, wallet actions, market observations, or claims about on-chain behavior.

## Procedure

1. Separate observed chain data from interpretation.
2. Publish transaction signatures when safe.
3. Avoid partnership, pump, or price-promise language.
4. Mark demo wallets as demo wallets.
5. Never replace missing data with placeholder zeros.
6. State what would change the interpretation.

## Verification

A claim needs one of:

- transaction signature,
- wallet address,
- mint/CA,
- public dashboard URL,
- reproducible script output,
- explicitly labeled uncertainty.

## Failure modes

- Chat sentiment gets treated as evidence.
- Placeholder metrics harden into lore.
- A dashboard becomes persuasion instead of instrumentation.
- A joke gets read as a promise because the market is tired and cannot be trusted with metaphors.

## Falsifier

If the public cannot independently inspect the named object, call it a hypothesis or a private observation. Do not call it a receipt.
